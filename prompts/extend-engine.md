# Промпт: добавить новый транспорт или новый мир в движок SpaceShip

Используй, когда нужен вид транспорта, которого нет в списке (вертолёт, самолёт, корабль, машина, мотоцикл есть), или новая среда (например, море, город, подземелье).

---

Ты добавляешь в движок SpaceShip новый элемент. Правила одинаковые для транспорта и для мира.

## Новый транспорт (src/vehicles/<имя>.js)

1. Создай файл по образцу `src/vehicles/car.js` (наземный) или `src/vehicles/plane.js` (воздушный).
2. Экспортируй объект `vehicle` с полями:
   - `label` — название по-русски для интерфейса.
   - `env` — `space`, `sky` или `road`. Мир должен существовать в src/env/index.js.
   - `control` — `fly` (курс, тангаж, крен; есть вертикальная тяга, если `spec.vertical` > 0) или `drive` (руление по земле, `spec.lean` даёт наклон).
   - `spec` — характеристики:
     - для `fly`: `cruise`, `boost`, `brake`, `accel`, `turn`, `pitchRate`, `roll`, `vertical` (0 — нет);
     - для `drive`: `cruise`, `boostSpeed`, `reverse`, `accel`, `turn`, `lean`;
     - общие: `kmh` (во сколько раз умножить скорость, чтобы получить км/ч на HUD), `hum` (частота гула, Гц), `autoSpeed` (скорость автопилота), `exhaust` (есть ли выхлоп из `nozzles`);
     - `camera`: `back` — смещение камеры от транспорта в его системе координат (`[x, y, z]`, +z — назад), `look` — куда смотреть вперёд, `orbit`, `orbitH` — кинематографический облёт до взлёта;
     - `dockView`: `dist`, `side`, `height`, `lookShift` — камера при стыковке с целью.
   - `build(accent)` — возвращает `{ group, nozzles, update(dt, t, state) }`:
     - `group` — THREE.Group с моделью. Нос смотрит в -Z, верх — +Y, размер в единицах сцены (самолёт ~14 единиц в длину, машина ~5).
     - `nozzles` — массив THREE.Vector3 в локальных координатах: откуда идёт выхлоп.
     - `update(dt, t, state)` — анимация: вращение винтов и колёс, мигание огней. `state` — текущее состояние полёта (`speed`, `mode`, `pos`, `quat`).
3. Модели строй из примитивов и материалов из `src/vehicles/shared.js` (`hull`, `dark`, `glass`, `neon`, `lathe`, `flare`, `result`). Внешних файлов моделей не добавляй.
4. Зарегистрируй транспорт в `src/vehicles/index.js` (в объекте VEHICLES).
5. Добавь его в `VEHICLE_ENV` и в `VEHICLE_COPY` в `src/core/content.js` (слово для подписи интро: «Я — …»).
6. Проверка: `npm run build`, затем `npm run dev` и открой `index.html?vehicle=<имя>&debug=1`. В консоли не должно быть ошибок. В `window.spaceship.ctrl.state` видно режим (`arrive` → `idle` → `free`).

## Новый мир (src/env/<имя>.js)

1. Экспортируй функцию `build(scene, { content, pixelRatio, accent })`. Она добавляет объекты в сцену и возвращает объект:
   ```js
   {
     name: 'имя',
     targets: [makeTarget({ id, kind, name, when, obj, radius, dockDist, accent, data, labelRange })],
     groundY,            // высота земли или моря; для вертолёта — минимальная высота
     spawn: { pos, yaw, arriveFrom },   // где стоит транспорт и откуда прилетает
     lights: [THREE.Light, ...],
     background,         // цвет фона (hex)
     fog: { color, density },
     update(dt, t)       // анимация мира
   }
   ```
2. Цели (`targets`) — одна на каждый проект, одна на `about` (`kind: 'about'`) и одна на контакты (`kind: 'contact'`). Порядок: about первым, contact последним. `obj` — THREE.Object3D, к которому стыкуются. `radius` — примерный размер; от него зависят подсказка «вход в орбиту» и обнаружение. `dockDist` — на каком расстоянии от объекта стоит транспорт при стыковке.
3. Используй `makeTarget` и палитры из `src/env/common.js`, текстуры и шейдеры — из `src/core/gfx.js`.
4. Зарегистрируй мир в `src/env/index.js` (объект ENVIRONMENTS).
5. Добавь имя в `ENVIRONMENTS` в `src/core/content.js` и укажи, каким транспортом он доступен (VEHICLE_ENV).
6. Проверка: `npm run build`, затем открой сайт с транспортом этого мира и посмотри, что проекты видны, подписи не перекрываются, стыковка работает (кликни по цели в списке маршрута).

## Что нельзя

- Не добавляй внешние модели (glTF, OBJ) и картинки, если их нет в репозитории: всё строится процедурно.
- Не ломай контракт: `build` возвращает ровно те поля, что перечислены выше. Контроллер полёта на них опирается.
- Не трогай `resolveContent` ради одного транспорта: достаточно записи в VEHICLE_ENV и VEHICLE_COPY.
- Не выводи приватные данные (репозитории, контакты, которых нет в конфиге).

## Что вернуть в ответе

- Какие файлы созданы и изменены.
- Какие транспорты и миры проверены в браузере, а какие нет.
- Что выглядит не так, если заметил (например, слишком яркий свет или низкий FPS на слабой видеокарте).
